# v0.1 实施与验收状态

日期：2026-10-05。交付范围：可运行的离线工程初版；**完整设计 v1 尚未全部实现/验收，不能启用真实资金交易**。测试及合成 demo 证明计算、状态与恢复机制，不能证明策略效果、真实数据能力或前瞻观察。

## 当前完成的工程链路

- Python 3.11 + 固定 RQAlpha 6.1.5，uv.lock；显式适配器注册、核心 Pydantic 契约、JSON Schema、CLI 与初始 SQLite migration。
- 规范 CSV、raw 保留、质量门禁、原子内容哈希快照、Parquet 与 DuckDB 查询、时点过滤。Tushare 原始接口分页缓存/重试/刷新与 Bar 单位转换。
- ETF 120 日趋势前二、主板股票流动性前 300 后 60 日低波动前五、ETF 固定清单与同股票候选池等权基准；非月末区分 NO_REBALANCE 与目标现金。
- 聚合账户额度、整手与零股、价格保护、流动性限制、未知委托阻断、费用/现金预留；买入不复用同日卖出款。股票/ETF T+1 经真实引擎合成案例验证。
- Decimal 事件账本、业务 ID 去重、原子投影、批次持仓、冻结、部分成交、晚到成交/费用、应收股利/到账、送转解锁原语、持久暂停和恢复记录。
- 人工清单 JSON/CSV/HTML、预检、手工提交登记，四类规范 CSV preview/apply 与三方数量/现金核对。未确认费用、订单累计量和快照不会当完成。
- 同一个 daily / paper step 编排，冻结每日输入和未来订单，重放前缀比较、重复日幂等、历史数据或执行代码/配置变化阻断、错过交易日阻断。历史回放与当天前瞻任务隔离。
- 实验 manifest、失败 INVALID 记录、代码/锁/参数身份、成本/延迟/本金压力套件、基准、指标、HTML 与 PNG/SVG 图；SQLite Backup API、文件哈希及恢复重放。

## 继续实施顺序

1. 补全公司行动/红利税/送转锁定及退市 Mod，按每笔、每日与独立账本对照，相关 INVALID 门禁通过测试后逐项开放。
2. 有 token 后逐接口探测权限、分页、时间、历史证券/状态/公司行动，完成 Tushare 多数据集拼接；全市场范围需独立审计证据，不能仅修改 scope 字符串。
3. 统一剩余 Provider 契约、证券版本映射、事件修订与关联；完善资金流 TWR、归因和 OS 封存隔离。
4. 接入脱敏真实券商样例和实际费率/初始批次、个人风控；开展前瞻 paper、调度与离机恢复演练。只在具体工程与策略版本均批准后，考虑人工账户启用。

没有数据账号、券商记录或市场观察时，不能用合成结果替代这些验收。v0.1 不包含自动实盘、LLM 自主研究、财报因子或 Windows 交易机部署。
